# Проверка приложения

## Автоматически

`npm test` запускает:
- pose: синтетические скелеты. Калибровка 1/3–3/3, нормальные циклы при разном размере
  корпуса, неполный цикл, джиттер, одно/оба запястья потеряны, низкая уверенность, руки и
  таз вне кадра, пауза, разрыв кадров, смена положения камеры.
- calibration: подготовка, отсчёт, три пробных свинга, timeout, повтор с 0/3, зелёная задержка, отмена и фон.
- game: 20 свингов → один разрушенный валун → новый валун; пауза, сброс.
- replay: запись числовых данных из приложения и её офлайн-повтор (`tools/replay.cjs`) дают тот же счёт.
- onboarding: front camera, загрузка модели, прогресс 1/3–3/3, пробные свинги без игрового
  счёта, автостарт, жёлтая подсказка при потере рук, пауза/фон без инференса, неудача с
  конкретной подсказкой, ошибка модели с повтором (без optical flow), ошибки инференса,
  закрытие, поздний результат камеры после отмены, отказ разрешения.

Эти тесты не используют реальную камеру и реальную модель: tests/harness.cjs запускает app.js в Node VM
с заглушками DOM/Canvas/PoseTracker. Они не проверяют Safari, качество модели на людях
с гирей или производительность. Вручную в Chromium (Playwright, фото как «камера»)
проверены: загрузка модели, совмещение overlay с зеркальным видео, режим проверки файла.

## Проверка записанного видео

«Проверить записанное видео» в панели справа: результат (метки свингов, статусы кадров,
время инференса) сравнивать с ручной разметкой. Это воспроизводимый способ оценки на
реальных роликах; пока ни одного размеченного ролика нет.

## Ручная проверка на iPhone 13

Записать версию iOS/Safari, ракурс, освещение, разрешение видео, версию модели
(после её внедрения). Нужен HTTPS. Не сохранять/отправлять видео без согласия.

1. Первый запуск: запрос камеры без микрофона, именно фронталка, зеркальное превью.
2. Пока ставишь телефон, игра и счётчик неподвижны.
3. Загрузка модели, затем кнопка «Я готов» включается, когда в кадре видны плечи, таз и запястья.
   Точки на превью совпадают с телом, превью зеркальное. Выключить сеть до первого запуска:
   должна быть ошибка модели с повтором.
4. Отсчёт 3 с → три пробных свинга (1/3, 2/3, 3/3) → зелёный экран и автостарт; счётчик 0.
   Без свингов за 40 с — красный экран с подсказкой.
5. 10 настоящих свингов в обычном темпе: вручную записать число замеченных,
   пропущенных и лишних срабатываний. Повторить несколько подходов.
6. Неполные движения, поправление телефона, наклон без свинга, руки вне кадра,
   остановка внизу, перекрытие запястий: проверить отсутствие случайных ударов.
7. Разные расстояния, свет, темп и фон; фиксировать условия проблемного случая.
8. Свернуть Safari на проверке и в игре: не должно быть скрытого запуска/счёта.
9. Запретить камеру, отменить запрос, закрыть настройку, повторить вход.
10. 20 игровых свингов: разрушение валуна и продолжение следующего.
11. Звук, fullscreen, поворот экрана, пауза и reset.
13. Режим «телефон + экран» (docs/REMOTE.md): подключение по QR-ссылке (также из разных сетей: мобильный интернет у телефона), прогресс 1/3–3/3 и
    подсказки на компьютере, 20 свингов, пауза/сброс с экрана, обрыв Wi-Fi и повторное подключение,
    поведение Safari при сворачивании. Записать, если Wi-Fi с изоляцией клиентов блокирует связь.
12. Записать на iPhone: время инференса (среднее/пик) и число пропущенных кадров из панели,
    нагрев, плавность анимации; сравнить CPU и `?delegate=gpu`.

Для сравнения моделей использовать одинаковые размеченные ролики и контрольный
набор, который не использовался для подбора порогов. Метрики: precision/recall
событий, лишние/пропущенные свинги, ошибка общего счёта, задержка удара, время
обработки кадра, нагрев и стабильность длительного подхода. Не считать FPS
самостоятельным доказательством точности.

## Известные ограничения проверки экспорта

Синтаксис и тесты повторно запущены при сборке архива. Мобильный UI ранее проверен
в браузерном iframe шириной 390 px. На физическом iPhone эта среда не тестировала
приложение. Точность нового счёта по позе на реальных свингах не измерена.
