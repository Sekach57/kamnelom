## MediaPipe Pose Landmarker

Первый кандидат для веб-приложения. Пакет `@mediapipe/tasks-vision` определяет
ориентиры тела в изображении/видео. Официальный web sample указывает Safari
и iOS 16+. Это не гарантия нужной частоты кадров на iPhone 13: нужен замер.

- Web guide: https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js
- Sample / requirements: https://github.com/google-ai-edge/mediapipe-samples/blob/main/examples/pose_landmarker/js/README.md
- Model overview: https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker

`detectForVideo` синхронный и может блокировать интерфейс. Документация рекомендует
Worker для видеопотока. Нужно проверить передачу кадров, работу выбранного backend
и Worker на Safari; не считать перенос в Worker автоматически решённым.

## MoveNet / TensorFlow.js

Кандидат для сравнительного теста. 17 точек, включая плечи, локти, запястья и таз.
Lightning ориентирован на меньшую задержку, Thunder — на точность. Нужно сравнить
оба с MediaPipe на одних и тех же роликах, не только сравнивать заявленный FPS.

- https://github.com/tensorflow/tfjs-models/blob/master/pose-detection/src/movenet/README.md
- https://github.com/tensorflow/tfjs-models/blob/master/pose-detection/README.md
- https://www.tensorflow.org/hub/tutorials/movenet

## Apple Vision

Вариант для будущего нативного iOS-приложения; не drop-in библиотека для сайта.
Возвращает положения частей тела и confidence, но логику упражнения всё равно
нужно писать отдельно.

- https://developer.apple.com/documentation/vision/detecting-human-body-poses-in-images

## Предлагаемый алгоритм поверх модели позы

1. Проверять наличие одного человека и уверенность важных точек.
2. Отслеживать запястья относительно плеч и таза, нормализовать по размеру корпуса.
3. Обрабатывать перекрытие запястий: не усреднять уверенную точку с потерянной;
   не продолжать подсчёт по выдуманной траектории при длительной потере.
4. Калибровать рабочую амплитуду по трём циклам, не зашивать пиксельные пороги.
5. Сглаживать координаты без чрезмерной задержки; настроить гистерезис.
6. Состояния верх → движение вниз → низ → возвращение вверх → один удар.
7. Сбрасывать неполный цикл после длительной потери, паузы или перемещения камеры.
8. Показывать overlay точек и конкретные состояния: «не вижу руки», «нижняя точка
   вне кадра», «движение замечено». Не заявлять оценку техники упражнения.

Фронтальный ракурс оставляем по требованию пользователя. При нём гиря и руки
могут перекрывать друг друга; модель позы не гарантирует устранения этой проблемы.
Детектор тела также не доказывает, что в руках именно гиря. Для текущей игры
счётчик циклов движения рук — целевой уровень, распознавание предмета не реализовано.
